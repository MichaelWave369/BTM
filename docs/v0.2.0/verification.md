## Preserved repairs

See [failures-and-repairs.md](failures-and-repairs.md). In particular, the full traversal uncovered Warden phases stalling during stun, and the first normal-browser capture test found a timer binding error that pure injected-timer tests did not catch. Both were corrected and retested.

## Not verified

- A full human-controlled six-sector playthrough, subjective combat balance, audio quality on real speakers/headphones and sustained performance on the user's PC.
- Successful native pointer lock and fullscreen in this restricted browser. Denial/fallback and drag input were observed; success-path policy is covered by unit tests, which is a narrower claim.
- Browser airplane-mode behavior on the deployed HTTPS game. The preview is HTTP on a non-localhost hostname and cannot activate a service worker. The generated worker and its complete runtime cache were executed under Node with disconnected fetch; that is a logic check, not a browser offline certification.
- Cross-browser, mobile/touch, gamepad, Quest or hardware integration. No such compatibility claim is made.
- Normal-game result-screen transitions were covered by production state/progression logic and source checks; the automated traversal renderer does not operate every result-screen button through native browser clicks.

The latest Site metadata reports a public audience; that current audience is preserved for this update. The downloadable project/build runs locally without a login. No external runtime dependency or paid service was introduced. Final native deployment success is reported separately in delivery; a sign-in gate does not prove a gameplay failure.
