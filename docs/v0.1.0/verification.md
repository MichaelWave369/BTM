Local preview is HTTP on a non-localhost hostname, which is not a secure service-worker context. Its footer correctly reports LOCAL BUILD instead of promising offline caching. Cache activation requires HTTPS or localhost. Native hosting reported a successful private deployment. The cloud browser reached the host's ChatGPT sign-in gate, so HTTPS service-worker activation could not be verified in that browser. The portable/local game itself does not require authentication.

No application JavaScript errors were observed in the captured browser logs. The cloud browser emitted extension metadata errors, unrelated to game source. Audio controls were exercised, but this does not claim an independent listening review or verified browser audio output on every device.

## Preserved failures and repairs

1. The first preview server did not honor the platform's `--port 4173` argument and launched on 5173. The server now parses `--port`; restarting the managed preview succeeded.
2. A new crawler regression test initially used a fixture from sector one, which has no crawler. The fixture now loads the actual crawler from sector three. The production phasing logic and regression test pass.
3. Inspection identified that navigation caches could survive sector changes. Load and restore now clear them.
4. Browser inspection showed the original aspect-ratio layout could push the HUD/footer below the viewport. Desktop viewport-height sizing now keeps them visible.
5. The initial offline footer could imply caching before a worker was active. It now reports CACHING, OFFLINE READY after activation, ONLINE on failure, or LOCAL BUILD when service workers are unavailable.
6. A final asset-path check caught the source ZIP before it had been generated. The source/build download is now generated by the dependency-free Node builder and checked with the rest of the static output. The ZIP is tested for integrity and rebuilt in an isolated checkout.
7. Dead-player checkpoint writes are rejected so a late combat event cannot overwrite a valid retry point. A regression test passes.
8. The renderer now groups wall ray stripes on larger canvas resolutions to reduce draw calls while retaining the intentionally chunky aesthetic.

## Limits

- These are author-run implementation checks. No independent proving-ground verification or commercial release-readiness claim is made.
- Browser progression checks intentionally position the player beside relays/key and remove the Warden via production damage logic. They verify gates and screens, not campaign balance or a human playthrough.
- A sustained manual three-sector combat playthrough, cross-device performance profiling, real Quest/controller support and an independent music/SFX review remain unverified.
- Native browser pointer lock was denied in QA; fullscreen depends on the host browser. Both failures are handled.
- The game's static bundle contains no login requirement. The default owner-private hosted Site can have a provider access gate; downloaded/local play is independent.
- The eventual Demiurge boss is deferred; the Warden is this candidate's final playable encounter.
